# 交互式加密/解密模式需求文档

## 1. 背景

当前项目已经支持通过命令行参数完成文件和目录的加密、解密、密钥生成、算法列表和文件信息查看。对于熟悉命令行的用户，现有命令可以正常使用；但普通用户需要记住参数、算法名称、输入输出路径和密码输入方式，使用门槛较高。

本需求新增一个交互式向导模式，让用户通过数字或方向键逐步选择语言、文件、操作类型、算法、密码和保存路径，从而在不理解完整命令参数的情况下完成加密或解密。

## 2. 功能目标

- 提供一个简单入口：`crypto -w`。
- 支持交互式选择，不要求用户记忆完整命令。
- 支持中文和英文界面。
- 支持输入数字选择，也支持方向键移动后回车确认。
- 支持将文件或目录拖入终端后自动得到路径。
- 支持加密和解密两种流程。
- 支持显示算法说明，帮助普通用户选择合适算法。
- 支持安全输入密码，密码不在终端明文显示。
- 支持选择输出保存路径，默认保存到当前路径。
- 不破坏现有命令、参数和行为。

## 3. 命令入口

### 3.1 主入口

```bash
crypto -w
```

`-w` 表示 wizard，即交互式向导模式。该短参数当前未被现有命令占用，适合作为普通用户入口。

### 3.2 长参数入口

```bash
crypto --wizard
```

长参数用于增强可读性，也便于在 README 或帮助信息中解释。

### 3.3 子命令别名入口

```bash
crypto wizard
```

可选实现。该入口用于适配当前项目以子命令为主的 CLI 风格，并降低 `crypto -w` 与现有参数解析结构的耦合。

### 3.4 帮助信息

`crypto --help` 需要展示交互式入口：

```text
-w, --wizard    Start interactive encryption/decryption wizard
```

中文语言下展示：

```text
-w, --wizard    启动交互式加密/解密向导
```

## 4. 用户流程

交互式模式必须按照以下步骤执行。

### 4.1 第一层：选择语言

启动后首先选择语言。

选项：

1. 中文
2. English

交互要求：

- 用户可以输入 `1` 或 `2` 后回车。
- 用户可以使用方向键选择，再按回车确认。
- 默认选中项建议为当前 CLI 默认语言；如果无法判断，则默认选中 English。
- 选择语言后，后续所有提示、错误信息、算法说明和确认信息都使用该语言。

### 4.2 第二层：选择文件或目录

语言选择完成后，提示用户输入要处理的文件或目录路径。

交互要求：

- 用户可以手动输入路径。
- 用户可以将文件或目录拖入终端，终端会自动填入路径。
- 需要兼容拖入路径带引号、反斜杠转义和空格的情况。
- 支持相对路径和绝对路径。
- 支持单个文件。
- 支持目录；当输入为目录时，加密流程默认等价于现有 `--recursive` 行为。

校验要求：

- 路径不能为空。
- 路径必须存在。
- 路径必须可读。
- 如果路径是目录，需要确认目录中至少存在可处理内容。
- 如果路径无效，显示错误原因，并允许用户重新输入。
- 用户可以输入 `q` 或 `quit` 退出向导。

中文提示示例：

```text
请输入要处理的文件或目录路径（可直接拖入终端）：
```

英文提示示例：

```text
Enter the file or directory path to process (you can drag it into the terminal):
```

### 4.3 第三层：选择加密或解密

文件选择完成后，提示用户选择操作类型。

选项：

1. 加密
2. 解密

英文：

1. Encrypt
2. Decrypt

交互要求：

- 支持数字选择。
- 支持方向键选择。
- 默认选项根据输入文件自动判断：
  - 如果输入路径以 `.enc` 结尾，默认选中解密。
  - 否则默认选中加密。
- 用户仍然可以手动覆盖默认选择。

### 4.4 第四层：选择算法

操作类型选择完成后，提示用户选择算法。每个算法需要显示简短说明。

#### 4.4.1 加密算法选项

加密流程应展示以下算法：

1. AES-256-GCM
   - 默认推荐。
   - 适合大多数文件和目录。
   - 具备认证加密能力，可检测文件是否被篡改。

2. ChaCha20-Poly1305
   - 推荐用于移动设备、低功耗设备或没有 AES 硬件加速的环境。
   - 具备认证加密能力。

3. AES-256-CBC
   - 主要用于兼容旧系统。
   - 使用 HMAC-SHA256 提供完整性保护。
   - 不建议普通用户优先选择。

4. RSA-OAEP-2048
   - 非对称混合加密。
   - 需要公钥加密、私钥解密。
   - 适合和他人共享加密文件的场景。

5. RSA-OAEP-4096
   - 非对称混合加密。
   - 安全余量更高，但速度更慢。
   - 适合长期保存或更高安全要求。

6. ECIES-P256
   - 非对称混合加密。
   - 密钥较短，效率较高。
   - 适合希望兼顾安全性和性能的非对称加密场景。

默认选择：

- 普通用户默认选择 `AES-256-GCM`。
- 如果用户选择非对称算法，需要额外提示选择公钥文件。

#### 4.4.2 解密算法处理

解密时优先从加密文件头中读取算法信息。

要求：

- 如果文件头包含算法信息，直接展示识别结果，不要求用户手动选择算法。
- 如果无法读取算法信息或文件格式不兼容，再让用户手动选择算法。
- 展示算法时，需要提示用户该算法来自文件元数据或来自手动选择。

中文示例：

```text
已识别算法：AES-256-GCM
```

英文示例：

```text
Detected algorithm: AES-256-GCM
```

#### 4.4.3 算法说明展示

算法选择界面需要在同一屏幕显示算法名称和一句说明。

示例：

```text
请选择加密算法：
> AES-256-GCM        默认推荐，适合大多数文件，支持篡改检测
  ChaCha20-Poly1305  适合移动设备或无 AES 硬件加速环境
  AES-256-CBC        兼容旧系统，不建议普通用户优先选择
```

如终端宽度较窄，说明文字可以换行，但不能影响选中和确认操作。

### 4.5 第五层：输入密码

算法选择完成后，提示用户输入密码。

#### 4.5.1 对称加密

加密时：

- 第一次输入密码。
- 第二次确认密码。
- 两次输入不一致时，提示错误并重新输入。
- 密码不显示在终端中。

解密时：

- 只输入一次密码。
- 密码不显示在终端中。
- 如果密码错误，显示解密失败或认证失败，并允许用户重试。

密码强度提示：

- 加密时，如果密码少于 12 个字符，提示风险。
- 用户可以选择重新输入或继续使用。
- 不强制阻止弱密码，避免影响可用性。

#### 4.5.2 非对称加密

当算法为 RSA-OAEP-2048、RSA-OAEP-4096 或 ECIES-P256 时：

- 加密流程需要选择公钥文件。
- 解密流程需要选择私钥文件。
- 如果私钥文件本身需要密码，后续版本可支持输入私钥密码；本期如现有密钥格式不支持，可暂不实现。

#### 4.5.3 密钥来源

交互式向导第一版默认使用密码方式或密钥文件方式：

- 对称算法：默认密码。
- 非对称算法：默认密钥文件。

环境变量密钥来源保留在高级命令行参数中，不作为普通用户向导第一版的默认流程。

### 4.6 第六层：选择文件保存路径

密码或密钥输入完成后，提示用户选择输出保存路径。

交互要求：

- 默认保存到当前工作目录。
- 用户直接回车时使用默认路径。
- 用户可以输入目录路径，也可以输入完整文件路径。
- 用户可以将目标目录拖入终端。
- 路径中包含空格时必须正确处理。

默认命名规则：

加密文件：

- 输入为 `example.txt`
- 默认输出为当前目录下 `example.txt.enc`

解密文件：

- 输入为 `example.txt.enc`
- 默认输出为当前目录下 `example.txt`

加密目录：

- 输入为 `Photos`
- 默认输出为当前目录下 `Photos.enc`

解密目录归档：

- 如果文件头包含原始目录名，则默认输出为当前目录下原始目录名。
- 如果无法读取原始目录名，则默认输出为当前目录下去掉 `.enc` 后缀的名称。

覆盖处理：

- 如果输出路径已存在，必须提示用户确认。
- 默认选择为不覆盖。
- 用户可以选择：
  1. 重新输入路径
  2. 覆盖
  3. 取消操作

### 5.1 中文加密示例

```text
$ crypto -w

> 中文
  English

请输入要处理的文件或目录路径（可直接拖入终端）：
/Users/me/Desktop/secret.pdf

请选择操作：
> 加密
  解密

请选择加密算法：
> AES-256-GCM        默认推荐，适合大多数文件，支持篡改检测
```

## 6. 交互控制要求

### 6.1 键盘操作

所有选择型步骤必须支持：

- 数字键选择。
- 上下方向键移动。
- 回车确认。
- `Esc` 返回上一步或取消当前选择。
- `Ctrl+C` 安全退出。

### 6.2 返回和取消

- 用户在任一步骤输入 `q`、`quit`、`exit` 可以退出。
- 对于选择型界面，`Esc` 优先返回上一步。
- 如果已经进入实际加密或解密过程，`Esc` 不应中断文件写入；中断应通过 `Ctrl+C` 处理，并清理临时文件。

### 6.3 终端兼容

向导需要在常见终端中可用：

- macOS Terminal
- iTerm2
- Windows Terminal
- Linux 常见终端

如果当前终端不支持方向键交互，需要自动降级为数字输入模式。

## 7. 安全要求

- 密码输入必须隐藏。
- 密码和派生密钥在内存中使用后应继续沿用现有安全清零机制。
- 不允许通过命令行参数明文传入密码。
- 不在日志、错误信息或调试输出中打印密码。
- 加密失败时不应删除原文件。
- 解密失败时不应覆盖已有有效文件。
- 文件写入应继续沿用临时文件和原子替换策略。
- 覆盖已有文件必须二次确认。

## 8. 错误处理要求

需要覆盖以下错误场景：

- 输入路径不存在。
- 输入路径不可读。
- 输出路径不可写。
- 输出文件已存在。
- 密码两次输入不一致。
- 密码错误导致解密认证失败。
- 加密文件格式不正确。
- 算法不支持。
- 非对称算法缺少公钥或私钥文件。
- 用户取消操作。
- 磁盘空间不足。

错误提示应满足：

- 使用用户已选择的语言。
- 说明具体失败原因。
- 对可恢复错误提供重试入口。
- 对不可恢复错误安全退出。

## 9. 与现有功能的关系

交互式向导不替代现有命令，而是封装现有能力。

内部行为建议映射到现有命令参数：

加密：

```bash
crypto encrypt -i <input> -o <output> -a <algorithm>
```

解密：

```bash
crypto decrypt -i <input> -o <output>
```

目录加密：

```bash
crypto encrypt -i <input_dir> -o <output> -a <algorithm> --recursive
```

非对称加密：

```bash
crypto encrypt -i <input> -o <output> -a <algorithm> -k keyfile --keyfile <public_key>
```

非对称解密：

```bash
crypto decrypt -i <input> -o <output> -k keyfile --keyfile <private_key>
```

## 10. 非目标

本需求第一版不包含以下内容：

- 图形界面。
- 批量选择多个不连续文件。
- 自动生成和托管密钥。
- 云端保存密码或密钥。
- 通过命令行参数直接输入明文密码。
- 替代现有高级命令行参数。

## 11. 建议实现方式

Rust 交互式终端库可选：

- `dialoguer`：适合选择菜单、确认、输入框、密码输入，易于实现。
- `inquire`：交互体验较好，支持选择和文本输入。
- `crossterm`：适合更底层的方向键和终端控制。

建议优先使用 `dialoguer` 或 `inquire`，避免自行实现复杂终端控制逻辑。

建议模块划分：

- `src/interactive.rs`：交互式向导主流程。
- `src/cli.rs`：新增 `-w, --wizard` 参数或 `wizard` 子命令。
- `src/app.rs`：新增 `run_interactive_wizard()` 或在现有 `Application` 上封装调用。
- `src/i18n.rs`：补充交互式文案。

## 12. 验收标准

### 12.1 基础验收

- 执行 `crypto -w` 可以进入交互式向导。
- 第一层可以选择中文或英文。
- 文件路径支持手动输入。
- 文件拖入终端后可以正确识别路径。
- 可以通过数字选择完成所有选择型步骤。
- 可以通过方向键和回车完成所有选择型步骤。
- 可以完成一次文件加密。
- 可以完成一次文件解密。
- 默认输出路径为当前工作目录。
- 加密默认算法为 `AES-256-GCM`。
- 解密时可以从文件头识别算法。

### 12.2 安全验收

- 密码输入不回显。
- 加密时需要确认密码。
- 密码不一致时不能继续加密。
- 解密密码错误时不会生成有效输出文件。
- 输出文件存在时默认不覆盖。
- 用户取消或 `Ctrl+C` 后不会留下未清理的临时文件。

### 12.3 兼容验收

- 原有 `crypto encrypt` 命令行为不变。
- 原有 `crypto decrypt` 命令行为不变。
- 原有 `crypto list-algorithms` 命令行为不变。
- 原有测试应全部通过。

## 13. 测试建议

### 13.1 单元测试

- 路径清洗：普通路径、带空格路径、拖入终端带引号路径、反斜杠转义路径。
- 默认输出路径生成：加密、解密、文件、目录。
- 操作默认值推断：`.enc` 默认解密，其他默认加密。
- 算法列表和说明文案完整性。

### 13.2 集成测试

- 模拟完整加密流程。
- 模拟完整解密流程。
- 模拟输出文件已存在并选择重新输入路径。
- 模拟密码确认不一致后重新输入。
- 模拟错误密码解密失败。
- 模拟目录加密和解密。

### 13.3 手动测试

- 在 macOS Terminal 拖入文件。
- 在 iTerm2 拖入文件。
- 在 Windows Terminal 拖入文件。
- 在终端宽度较窄时检查算法说明是否可读。
- 使用方向键选择每一层菜单。
- 使用数字选择每一层菜单。
- 使用 `Ctrl+C` 中断并确认临时文件清理。
